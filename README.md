# Autocheck MVP — интеграция с партнёрскими автосалонами

MVP микросервиса: парсит выгрузки из 1С (VIN, марка, пробег, дефекты и т.д.),
сохраняет в базу без дублей по VIN (upsert), отдаёт список машин через
веб-интерфейс. Два триггера загрузки — по расписанию и по запросу.

## Запуск (рекомендуется — Docker)

Нужен только Docker.

```bash
docker compose up --build
```

Откройте http://localhost:8000 — список автомобилей (база наполняется
демо-данными автоматически при первом запуске).

## Что внутри

- Веб-интерфейс: http://localhost:8000
- API-документация (Swagger): http://localhost:8000/docs
- Webhook/API-триггер (принудительная загрузка файла):
  ```bash
  curl -X POST http://localhost:8000/upload -F "file=@путь/к/файлу.csv"
  ```
- Cron-триггер: раз в 30 минут сканирует `data/uploads/incoming/` и
  автоматически импортирует новые CSV-файлы
- Upsert по VIN: повторная загрузка не создаёт дублей, только обновляет

## Запуск без Docker

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

## Формат файла выгрузки

CSV с колонками: `vin, brand, model, year, mileage, defects, dealer, price`

```bash
python scripts/generate_dataset.py --rows 50 --out data/uploads/incoming/test.csv
```

## Принцип работы

Сквозной пример на искусственно сгенерированном файле — от запуска до
попадания записей в базу.

**1. Запуск сервиса**

```bash
docker compose up --build
```

**2. Генерируем тестовый файл** (искусственные VIN, марки, пробег и т.д.):

```bash
python scripts/generate_dataset.py --rows 20 --out data/uploads/incoming/test.csv
```

**3. Отправляем файл в систему** — любым из триггеров:

- вручную через API:
  ```bash
  curl -X POST http://localhost:8000/upload -F "file=@data/uploads/incoming/test.csv"
  ```
- или просто оставляем файл в `data/uploads/incoming/` — его подхватит
  cron-триггер при следующем скане (раз в 30 минут);
- или отправляем боту в Telegram (см. раздел ниже) — этот канал, в
  отличие от первых двух, ничего не пишет в базу сразу, а сначала
  показывает предпросмотр.

**4. Программа проверяет файл** — на каждую строку:

- соответствует ли формату (обязательные колонки на месте, VIN валиден
  и т.д.) — если нет, строка считается ошибкой и в базу не идёт;
- есть ли уже такой VIN в базе — если есть, это не ошибка, а повтор:
  при записи он обновит существующую машину, а не создаст дубль.

**5. Программа выдаёт результат проверки** — сколько строк подошло,
сколько ошибок, сколько повторов и сколько по-настоящему новых записей.
Пример ответа (так это выглядит в Telegram-боте; через API — то же самое
в виде JSON):

```
Файл: test.csv
Всего строк: 20
✅ Валидных: 18
⚠️ Ошибок: 2 (битый VIN / не хватает обязательного поля)
🔁 Уже есть в базе (будут обновлены): 5
🆕 Новых записей: 13

Добавить в базу?  [Добавить]   [Отмена]
```

**6. Подтверждение — добавлять или нет.** Эта интерактивная развилка
(«Добавить» / «Отмена») реализована в Telegram-боте: пока не нажата кнопка,
в базу ничего не пишется — это read-only предпросмотр. При подтверждении
происходит upsert по VIN (новые строки добавляются, повторы обновляются),
при отмене — файл и сообщения с диалогом просто удаляются, база не
трогается. У триггеров API (`/upload`) и cron такого шага подтверждения
нет по замыслу — они рассчитаны на автоматическую, а не интерактивную
загрузку, и импортируют файл сразу же по тем же правилам валидации и
upsert.

## (Бонус) Telegram-бот

Дополнительный канал загрузки: клиент присылает CSV прямо боту, получает
предпросмотр статистики и подтверждает загрузку кнопкой. Требует токен
в `.env` (`BOT_TOKEN=...`):

```bash
python -m app.telegram_bot
```

## Хостинг и домен: известное ограничение

Проект разрабатывался и тестировался **локально** (`localhost:8000`), без
деплоя на публичный сервер и без собственного домена. Это касается не всей
функциональности одинаково:

**Не критично — работает полностью локально:**
Веб-интерфейс, API, Swagger, оба триггера загрузки (webhook и cron) и
upsert по VIN не зависят от домена или публичного хостинга вообще. Всё
из раздела «Запуск» выше — `docker compose up --build` или запуск без
Docker — работает на `localhost` без каких-либо дополнительных настроек
сети. Для проверки основного функционала задания домен не нужен.

**Ограничение — только для Telegram Mini App:**
Telegram требует, чтобы кнопка `WebAppInfo`/`MenuButtonWebApp` вела на
адрес по **HTTPS с валидным сертификатом** — `http://localhost` для этого
не подходит принципиально, это ограничение самого Telegram, а не проекта.

Для локальной разработки и демонстрации этот адрес пробрасывался наружу
через туннель (`ngrok` / `cloudflared`), который временно превращает
`localhost:8000` в публичный HTTPS-URL:

```bash
# один из вариантов, нужен только для Mini App внутри Telegram
ngrok http 8000
# или
cloudflared tunnel --url http://localhost:8000
```

Полученный URL прописывается в `.env` (`WEBAPP_URL=...`), после чего кнопка
в боте открывает фронтенд внутри Telegram.

Из-за этого у бонусной Mini App-фичи есть практические нюансы:
- адрес туннеля **временный** — при перезапуске `ngrok`/`cloudflared` он
  меняется, и `WEBAPP_URL` в `.env` нужно обновлять заново;
- бесплатные туннели периодически недоступны или лимитированы (в процессе
  разработки встречались `ERR_NGROK_3200` и `Cloudflare Tunnel error 1033`);
- для стабильной работы в проде это ограничение снимается покупкой домена
  и разворачиванием обычного HTTPS (например, через Caddy/Nginx +
  Let's Encrypt, или деплоем на любой облачный хостинг с готовым TLS) — в
  рамках тестового задания это осознанно не делалось, так как не входит в
  его объём.

Итого: если просто нужно посмотреть работу сервиса — домен и туннель не
нужны, `docker compose up --build` полностью самодостаточен. Туннель нужен
только если отдельно проверяется Mini App-кнопка внутри Telegram-бота.
